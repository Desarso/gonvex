## Summary
- **Versioned SQL migrations** are now applied during deploy and `gonvex dev` syncs, with checksum tracking, tenant/Control Plane scoping, and dry-run support.
- The **npm CLI** now ships `migrations/*.sql` in the source bundle and watches them for changes.
- **`gonvex dev` waits for the runtime** on cold starts, preventing connection-refused failures when the runtime is still compiling.
- Dashboard demo tables were renamed to avoid schema collisions in shared Control Plane development environments.

## Changes
- **Versioned SQL migrations** — Projects can add `migrations/NNNN_description.sql` files. Migrations run after declarative schema reconciliation and before the new function manifest activates. Each file must declare `-- gonvex:scope tenant` or `-- gonvex:scope control-plane`; missing directives fail validation. The runtime tracks filename, SHA-256 checksum, and applied timestamp in a `gonvex_migrations` table. An applied migration is never re-run, and a checksum mismatch fails the sync. Use `-- gonvex:no-transaction` for statements that PostgreSQL forbids inside a transaction (e.g., `CREATE INDEX CONCURRENTLY`). Newly provisioned tenants receive all deployed tenant migrations before becoming ready.
- **Dry-run inspections** — `gonvex dev --once --dry-run` reports pending migrations and validates checksums without applying schema changes, SQL, or the function bundle.
- **Gated empty-column cleanup** — An opt-in runtime flag `GONVEX_DROP_EMPTY_UNDECLARED_COLUMNS` enables dropping columns that are no longer declared in the schema, but only when they are empty (all NULL) across every registered tenant database (or the Control Plane database). Non-NULL values—including constants, empty strings, and zeros—always preserve the column.
- **npm CLI bundling and watch** — The npm CLI now includes `.sql` migration files in the source bundle and fingerprints them in watch mode, so adding or editing a migration triggers a re-sync immediately instead of waiting for an unrelated `.go` change.
- **Dev startup resilience** — When running `gonvex dev` with a child command, the first sync now retries connection-level failures for up to 60 seconds. This prevents `make dev` cold starts from exiting when the runtime is still binding its port. Rejected syncs (bad key, invalid schema) still fail immediately.
- **Dashboard demo schema** — Renamed internal demo tables from `tasks` and `files` to `dashboard_demo_tasks` and `dashboard_demo_files` to prevent conflicts with user tables in shared Control Plane development environments.

## Technical Notes
- All published npm packages (`@gonvex/cli`, `@gonvex/client`, `@gonvex/protocol`, `@gonvex/react`, `create-gonvex`) are bumped to `0.1.29`.
- The Go CLI already shipped migration files; this release brings the npm CLI into parity.
- Migration execution order: declarative schema reconciliation → SQL migrations → manifest activation. Control Plane migrations run first; tenant migrations run fleet-wide with per-project sync locks and per-database advisory locks to prevent overlap. Tenant failures are collected and reported, but healthy tenants are not blocked.
- Added `docs/migrations.md` with documentation on file naming, scope directives, transaction handling, and dry-run usage.
