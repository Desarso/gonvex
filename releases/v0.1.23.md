## Summary
- **Recovers from wedged IndexedDB**: Sync subscriptions no longer remain permanently empty when the browser's IndexedDB store hangs; they now fall back to a full server snapshot after a 1-second timeout.
- **Cold open fallback**: If warm cache reads or directive recovery stall, the client abandons the cache attempt and opens a cold sync connection to ensure data is served.
- **Discards stale late reads**: Results arriving after the timeout are ignored to prevent race conditions with fresh server data.

## Changes
- Added a 1-second deadline to warm IndexedDB reads for sync collections and query directive recovery. If the store does not respond (observed in Chrome when the origin's backing store wedges), the client clears the pending operation and initiates a cold `sync.open` request instead.
- Updated all packages (`@gonvex/client`, `@gonvex/react`, `@gonvex/protocol`, `@gonvex/cli`, `create-gonvex`) to v0.1.23.

## Technical Notes
- Introduced `syncStoreReadTimeoutMs` constant (1000ms) in `@gonvex/client` to guard against IndexedDB `open()` calls that emit no events (neither success nor error), which was observed to leave sync collections empty while plain queries continued working.
- Added integration test simulating a hung store to verify cold-open fallback behavior.
