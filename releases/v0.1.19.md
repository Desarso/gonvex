## Summary
- Fix silent message loss in the WebSocket client during reconnects and stuck auth states
- Ensure invalidation-triggered query reruns always fetch fresh data instead of stale cache entries
- Restore end-to-end functionality for `npm create gonvex` quickstart (template dependencies, API shape, project ID wiring)
- Allow runtime admin and local developer keys to create slug-addressed tenants on modern UUID projects

## Changes
- **WebSocket reliability**: The client now queues non-auth messages when the socket is missing or closed and triggers a reconnect instead of silently discarding them. A 10-second watchdog prevents auth handshakes from stalling indefinitely if the server drops the response.
- **Query cache consistency**: Reruns triggered by table invalidations now bypass the cache and recompute results, preventing pre-mutation stale data from being served back to subscribers.
- **Tenant provisioning**: Modern projects now accept slug tenant IDs (e.g., `e2e-parallel`) when provisioning via the runtime admin key or local developer credentials; dashboard and native sessions continue to require UUID v6 tenant IDs.
- **Dashboard auth**: Fixed project discovery failing immediately after a Google native session restore due to an unvalidated cached access token.
- **Quickstart template**: Fixed the Vite React template to use the correct `@gonvex/cli` dev dependency, nested `api.messages.list` bindings, pass the project ID to `GonvexClient`, and generate complete scoped schema modules.

## Technical Notes
- `@gonvex/client`, `@gonvex/cli`, `@gonvex/protocol`, `@gonvex/react`, and `create-gonvex` all bumped to `0.1.19`.
- WebSocket `sendNow` now distinguishes `CLOSING`/`CLOSED` from `CONNECTING`; the former queues into `pendingMessages` and reconnects, while the latter waits for the `open` event.
- `authInFlight` is now guarded by `armAuthWatchdog`, which reissues auth or reconnects after 10 seconds.
- Runtime WebSocket handler tracks `tenantPinned` to avoid falling back to a pre-auth default tenant that is not related to the project.
- `executeTenantQueryForCallerCached` skips the cache read when `reason == "invalidate"`, recording a `"bypass"` metric instead.
