## Summary
- Sync operations now report calls, duration, and errors to the dashboard, correcting zero-traffic reporting for `sync.*` functions.
- Reduced upload traffic during reloads: collections with more than 16 rows now send only a 64-byte digest on resume, with the server requesting full hashes only when data differs.

## Changes
- **Dashboard metrics**: `sync.open` operations are now recorded in per-function metrics. Previously, sync traffic appeared as zero in the dashboard despite serving every reload; metrics now accurately reflect call volume, duration, and errors for sync paths.
- **Sync resume optimization**: Lowered the compact sync integrity threshold from 256 to 16 rows. Collections exceeding this limit resume with a 64-byte digest instead of full row hash maps. The server verifies digests against unchanged data and only requests specific hashes via `sync.needHashes` when differences exist, eliminating multi-kilobyte uploads per collection on every reload.

## Technical Notes
- All packages (`@gonvex/client`, `@gonvex/cli`, `create-gonvex`, `@gonvex/protocol`, `@gonvex/react`) bumped to v0.1.22.
- Client: `compactSyncIntegrityThreshold` constant reduced from `256` to `16`.
- Server (`sync.go`): Added `recordFunction` instrumentation in `openSyncWithClock` to capture sync open metrics.
