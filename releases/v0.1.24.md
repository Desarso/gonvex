## Summary
- Eliminated excessive IndexedDB storage growth during reloads by skipping redundant row writes when sync data is unchanged
- Fixed issue where quiet reloads could accumulate gigabytes of superseded data (observed: 1.5 GB across 673 SST files) due to LevelDB compaction delays  
- All packages bumped to v0.1.24

## Changes
- **Smarter sync persistence**: When a collection’s rows are byte-identical to what is already stored, only the sync cursor advances instead of deleting and re-inserting every row. This prevents IndexedDB from retaining superseded versions until compaction runs.
- **Reduced storage churn**: Previously, every `sync.ready` triggered a full rewrite of all rows for every collection on every reload. The store now detects unchanged rows and performs metadata-only updates, drastically reducing write amplification.

## Technical Notes
- Added `rowsUnchanged?: boolean` to the `StoredSyncCollection` schema; when set, `DexieSyncStore` updates only cursor, keyField, mode, and hashes without touching row data
- Subscriptions now track `persistedRows` to detect when the in-memory row array matches the stored array (covers both cache resumes and delta-applied batches)
- Version 0.1.24 released for `@gonvex/client`, `@gonvex/react`, `@gonvex/protocol`, `@gonvex/cli`, and `create-gonvex`
