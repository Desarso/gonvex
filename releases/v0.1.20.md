## Summary
- **Batch operations**: Queries and mutations now support batching (`subscribeMany`, `mutationMany`) to collapse multiple WebSocket frames into one, cutting overhead on route reloads and offline mutation flushes.
- **Durable sync across deploys**: Sync collections now survive code deploys without a full resync; storage is keyed by project/tenant/user scope instead of bundle epoch, eliminating the “every other reload is slow” issue during development.
- **Live query correctness**: Fixed a bug where returning a list to its original state after CRUD operations could leave stale data rendered; revisions now track the last delivered payload rather than the subscribe-time snapshot.
- **Dashboard error tracking**: Errors inbox now filters by release version and displays execution context (execution IDs, request payloads) for runtime failures.

## Changes
- **Client protocol**: Added `query.subscribeMany` and `mutation.callMany` (mirroring `sync.openMany`, 256-item bound) advertised via `queryBatch`/`mutationBatch` capabilities; falls back to single frames on older runtimes.
- **Durable sync**: Sync persistence and warm reads now use a `syncScope` (project, tenant, user, permissions) separate from the query cache generation, so auth or code changes reset only what is necessary.
- **Live queries**: Unchanged-payload checks now compare against the live delivered revision stored in the connection’s subscription map, ensuring accurate `query.progress` vs `query.result` decisions after deduplication.
- **Dashboard**: Added release filter dropdown to error groups, display of execution context and tags in error detail views, and protocol-specific logging for sync snapshots.
- **Runtime hardening**: Sync protocol hardened against delayed frames, oversized batches, and corruption; resume safety verified via authoritative digest checks and row-level reconciliation.
- **Deployment automation**: GitHub Actions workflow now deploys every successful `main` push to Coolify with exact commit SHA pins and semantic Compose validation.

## Technical Notes
- **npm/CLI**: Client packages (`@gonvex/client`, `@gonvex/react`, `@gonvex/protocol`) updated to support batch operations and durable sync scope keys; protocol version capabilities negotiated on connection.
- **Schema**: `notifySchemaVersion` bumped to `"3"` in generated manifests to support new sync durability features.
- **Release process**: Runtime deploys are automated via `scripts/deploy-coolify.mjs` with `GONVEX_DEPLOY_SHA` pinning and `docker-compose.coolify.yml` semantic verification; protected environment `gonvex-runtime` stores `COOLIFY_API_TOKEN`.
