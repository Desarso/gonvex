## Summary
- Recover warm query cache during offline cold starts using identity hints when JWTs are unavailable  
- Fix React provider blocking UI indefinitely when token fetch fails (e.g., offline identity provider)  
- Enable resilient local-first reads by preserving existing client auth when token refresh is unreachable  

## Changes
- **Offline cache recovery**: When starting offline without a usable JWT, you can now supply an `identity` hint containing the `sub` and `iss` claims of the last known token. The client uses these non-secret claims to derive the same cache identity key as a JWT would, recovering warm query directives and serving cached reads without network access.
- **Resilient React auth**: `ConvexProviderWithAuth` now catches token fetch failures and renders the application instead of holding the UI in a loading state forever. The client's existing authentication remains untouched, allowing local-first data to stay accessible when the identity provider is unreachable.

## Technical Notes
- All packages bumped to v0.1.25 (`@gonvex/client`, `@gonvex/react`, `@gonvex/cli`, `@gonvex/protocol`, `create-gonvex`)
- New optional `identity?: { sub: string; iss?: string }` field in `GonvexClientAuth`; hints are client-side only and never transmitted to the server
- Token parsing takes precedence over identity hints when deriving cache scope; both paths must derive identical keys for the same user
- `ConvexProviderWithAuth` now includes a rejection handler in the `fetchAccessToken` promise chain to release children on network errors
