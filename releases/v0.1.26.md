## Summary
- Add durable offline mutation outbox with optimistic UI updates that survive page reloads and reconnects
- Surface sync budget truncation so clients know when server-side row/byte limits cap a collection  
- Introduce error severity levels (error/warning) and optional Firebase ID token verification
- Support async `fetchToken` callbacks for automatic JWT refresh on every reconnect

## Changes
- **Offline mutations & optimistic updates**: The client now queues mutations locally when the socket drops (using IndexedDB/Dexie), replays them on reconnect with exponential backoff, and applies optimistic patches immediately to sync subscriptions. Includes crash recovery for interrupted sends, per-entity causal ordering to prevent write races, and a memory-only fallback when persistence is disabled. Optimistic state is rebuilt from the outbox after a page reload.
- **Sync truncation visibility**: The server reports when a collection hits its `maxRows` or `maxBytes` budget via a new `truncated` flag in `sync.ready` frames; clients no longer infer completeness from row counts alone. Codegen produces an `optimisticPatchesFor(path, args)` helper derived from each mutation’s `Writes()` declaration so optimistic patches can be applied without hand-written updaters.
- **Error tracking**: Added severity levels (`error`, `warning`) to error events and groups, exposed on the group API and filterable via `?level=`. The dashboard renders warnings in the existing warning color and defaults to showing all levels when the parameter is absent, preserving compatibility with older runtimes.
- **Authentication**: 
  - Server: Firebase ID tokens are now verified against the securetoken JWKS when `GONVEX_FIREBASE_PROJECT_ID` is set; deployments that omit the variable retain the previous behavior (unverified decode) so local and self-hosted setups are unaffected.
  - Client: New `fetchToken` option re-fetches the JWT before every auth send—on first connect, every reconnect, and once more with `forceRefreshToken: true` after a rejection—so long-lived sockets reauthenticate with live credentials instead of replaying expired tokens.
- **Reliability**: Fixed a bug where the sync listener failed to reconnect after tenant route changes.

## Technical Notes
- All npm packages bumped to `0.1.26`
- Protocol schema version bumped to `4` (`notifySchemaVersion` in generated manifests)
- New exports in `@gonvex/client`: `optimistic.js`, `outbox.js`, and `signals.js` (proxy-free reactive primitives: `signal`/`computed`/`effect`/`batch`); `@gonvex/react` adds `useSignal.ts` adapter over `useSyncExternalStore`
- Server database: `errors` and `error_groups` tables gain a `level` column deployed via `ADD COLUMN IF NOT EXISTS`; fingerprints hash the level only for non-error severities to avoid invalidating existing groups
- Environment: Set `GONVEX_FIREBASE_PROJECT_ID` to enable Firebase token signature verification; leave unset to preserve legacy auth behavior
- Idempotency: Outbox entries persist original idempotency keys across retries and browser sessions, making accidental cross-tab double-sends server-safe
