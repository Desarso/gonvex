---
title: Queries, Reducers, and Actions
description: Gonvex's three executable function kinds and generated bindings.
---

Gonvex application code has three executable function kinds.

## Query

Queries are one-shot and read-only. Gonvex runs them in a repeatable-read,
read-only Postgres transaction.

```go
app.Query("tasks.get", GetTask)
```

```tsx
const task = useQuery(api.tasks.get, { id });
```

## Reducer

Reducers are the only normal durable write path. Each call receives one
`ctx.Tx`; raw database pools are unavailable so all application-table writes
belong to the same transaction.

```go
app.Reducer(
  "tasks.rename",
  RenameTask,
  gonvex.OptimisticReducer("tasks").RowIDArg("id").FieldsArg("patch"),
)
```

Every public Reducer needs optimistic metadata. A rare operation that cannot
safely predict UI state must declare a reviewed reason with
`OnlineOnlyNonOptimistic(reason)`.

## Action

Actions perform HTTP, email, AI, file, and other external work. They do not
receive application database handles. To change durable state, call a Reducer:

```go
_, err := ctx.Reducers.Call(ctx, "tasks.markDelivered", args)
```

Reducers enqueue external work with `ctx.Outbox.Enqueue(...)`; the durable
outbox worker invokes the Action after commit and retries failures.

## Generated React surface

```tsx
useQuery(api.tasks.get, args)
useLiveQuery(api.tasks.grid, args)
useReplicaCollection(api.tasks.recent, args)
useReducer(api.tasks.rename)
useAction(api.mail.send)
```

`Writes`, manual invalidation, refetch-after-write, and raw subscription
lifecycle APIs are not part of the application model.
